# 实时选型与排名

训练记忆停在某个截止日期，而模型、工具和榜单按周更新。凭记忆回答“现在最好的是哪个”，最常见的错误不是排序错，而是漏掉截止日期之后出现的新实体，或者把已被取代的版本当成榜首。这个技能把记忆降级为“待核实的种子名单”，结论只来自能打开、带日期的来源。

## 1. 定下“今天”和问题

- 从系统提示或 `date` 取今天的日期，结论一律写“截至 YYYY-MM-DD”。
- 把“功能”翻译成可测的指标。例如：写代码 → SWE-bench Verified、Terminal-Bench、Arena Code；便宜又快 → 每百万 token 价格、输出速度；中文检索 → MTEB 的中文子榜。用户没说看重哪个维度时，按最可能的理解先做，并在结论里写出用了哪些指标。
- 记下硬约束：开源或可本地部署、语言、预算、上下文长度、许可证、地区可用性。约束经常比总分更能决定答案。

## 2. 记忆只当种子

先列出记忆中的候选，标为“待核实”。默认每个候选都可能已有新版本，榜首也可能已被你不认识的实体取代。这一步只用来生成检索词，不产出结论。

## 3. 实时检索

按顺序进行，证据足够时即可停止。各来源的地址、接口和口径说明见 [references/sources.md](references/sources.md)，开始检索前先读与本题相关的部分。WebSearch 提供更彻底、更新鲜的模式（如 `extended`）时，这类时效性问题值得用它。

1. **聚合榜**：先查 BenchLM，优先用它的 JSON 接口取对应分类的排名。它有 provisional 和 verified 两条榜，引用时注明是哪一条。
2. **一手榜单**：对结论起决定作用的指标，打开该基准自己的排行榜核对。聚合站可能滞后，也可能换算了口径。
3. **补漏新实体**（本技能的重点）：
   - 检索词带上当前月份和年份，如 `<功能> <基准名> <月份 年份>`、`new <类别> released <月份 年份>`、`<榜首候选> vs`，中英文各搜一次。
   - 看排行榜的 changelog 或新增条目、厂商的发布说明。
   - 对每个种子候选搜一次它的后续版本。
   - 新发现的实体回到第 1、2 步补齐分数。
4. **领域不在清单里**：搜 `<功能> leaderboard <年份>` 或 `<功能> benchmark <年份>`，优先选由基准作者维护、写有更新日期的页面。找到可靠的新来源时，把它补进 sources.md。

## 4. 判断新鲜度

每个数据点都要有日期：页面的最后更新时间、条目提交日期或发布日期。与今天比较：

| 领域 | 超过多久视为过时 |
| --- | --- |
| 前沿大模型、编码与智能体 | 30 天 |
| 向量、语音、OCR、图像等专项模型 | 90 天 |
| 库、框架、数据库、云服务 | 180 天 |
| 标准、协议、规范 | 365 天 |

过时信号：页面没有日期；榜首是一个你已在别处看到新一代的旧版本；转载站或 SEO 汇总页的表格；百科信息框里的“最新版本”；数字只出现在搜索摘要里，原页没有打开。过时数据可以作为背景列出，但不能单独支撑结论。

反过来，不认识的名称不等于错误，它可能晚于你的训练数据。到厂商官方页面或发布说明确认它存在及发布日期；确认之前标为“待确认”，不要擅自改成你熟悉的名字。

## 5. 交叉核对

- 榜首结论至少需要两个相互独立的来源；只有一个时标注“单一来源”。
- 区分厂商自报、第三方独立运行和榜单 verified。三者冲突时以后两者为准，并写出差异。
- 只比较同口径的数字：同一基准版本、同一评测框架（agent scaffold）、同一设置（如 pass@1、是否允许工具）。同一模型在不同推理档位（effort、思考预算）下分数不同，表格里写明档位。
- 分差落在误差范围内，或榜单头部已接近饱和时，写“并列”，不要硬排名次。
- 使用量榜（如 OpenRouter）反映采用度，人类偏好榜（如 LMArena）受回答风格影响，二者都不等于能力分。用途不同，分开表述。

## 6. 输出

使用下面的结构。简短问题可以压缩，但日期、来源、未能获取的部分和复查时间不要省略。

```markdown
**结论（截至 YYYY-MM-DD）**：一两句话，按用户的约束给出推荐；有并列就写并列。

| 候选 | 关键指标（口径） | 来源 | 数据日期 | 核实程度 |
| --- | --- | --- | --- | --- |
| <名称> | <基准名 分数（版本、框架）> | [<站点>](<链接>) | <YYYY-MM-DD> | 独立运行 / verified / 厂商自报 / 仅摘要 |

**近期变化**：最近一个时效窗口内新出现或换代的候选。
**与记忆的差异**：原先以为……，实际是……；没有差异就写“无”。
**未能获取**：哪些来源没打开、原因，以及结论因此可能缺什么。
**建议复查**：<今天加上该领域的时效窗口>，或某个事件之后（如某模型正式发布）。
```

## 7. 来源打不开时

- WebFetch 报 `getaddrinfo ENOTFOUND <host>`、403 或被代理拒绝，通常是运行环境的网络策略拦截了该域名。告诉用户被拦的域名，并说明可以在云端环境设置的 Network access 中把它加入允许的域名；同时改用 WebSearch 继续。
- 只来自搜索摘要的数字标为“仅摘要”。
- 缺失的数字不要用记忆补上，写“未获取”。用户要的是能核对的结论，一个看似完整但混入旧数据的表格比留空更有害。

## 8. 与决策记录配合

用户在为项目做选型时，提议把结果写进决策记录。仓库里有 MADR 模板（如 `templates/madr-full.md`）时：候选写进 Considered Options，表格与数据日期写进 Pros and Cons of the Options 或 More Information 的“证据与置信度”，复查日期写进“重审条件”。这样日后能看出结论基于哪一天的数据。
